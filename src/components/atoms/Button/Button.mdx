# Button

The only button atom. Every call-to-action, form submit, and filter toggle in the system routes through `variant`. When you need an element that looks like a button but navigates, use `as='a'` — the rendered HTML will be `<a>`, not `<button>`.

---

## Variants

### Ghost

The default. Use for secondary actions — "See all posts", "View on GitHub", nav-adjacent CTAs where you want a visible control but don't want to compete with a primary action. On hover the text turns violet; that's the only visual affordance beyond the border.

<Canvas of={ButtonStories.Ghost} />

### Primary

One per view. Reserved for the single most important action — the hero CTA, the Ask submit. Using more than one primary on the same screen competes with itself; reach for ghost for the secondary action.

<Canvas of={ButtonStories.Primary} />

### Chip

A filter toggle. Used in `FilterChipGroup` on the writing index. Pill-shaped, monospace, muted by default. Pressed state is surface-fill + full-text color — not the accent, just elevated contrast. The `pressed` prop maps directly to `aria-pressed`.

<Canvas of={ButtonStories.ChipPressed} />

## Sizes

`md` is the default and matches the mockup's base button. Use `sm` for tight layouts — chip counts, inline toolbars, footer actions.

## With icons

Pass Lucide icon names as `iconLeading` or `iconTrailing`, or provide custom SVG through the named slots if you need something non-standard. The component renders icons inside the flex container with a `0.4rem` gap, and 20px is the correct icon size for buttons per the iconography spec.

## As anchor

When the action navigates, pass `as='a'` and `href`. This renders a semantic `<a>` — correct for screen readers and right-click behavior. The visual appearance is identical to the `<button>` variant. Do not use `<button onclick="navigate()">` when a link is the right element.

<Canvas of={ButtonStories.AsLink} />

---

## Disabled

The disabled state uses `aria-disabled="true"` and `tabindex="-1"` rather than the native `disabled` attribute. This keeps the element in the DOM for screen readers while removing it from the tab sequence. `pointer-events: none` prevents mouse interaction.

Note: an `<a>` with `disabled` strips its `href` — without `href`, the anchor loses its link role, which is correct (a disabled link shouldn't be navigable).

## Don'ts

- **Two primary buttons side by side.** One primary, one ghost. The system has one accent.
- **Chip as a navigation link.** Chips are toggles. Use `ghost` with `as='a'` for nav.
- **Wrapping text inside a button.** Buttons should be short labels. If your copy is long, it's probably not a button.
- **`<button onclick="location.href=...">` for navigation.** Use `as='a'` + `href`.
